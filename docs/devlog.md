## 第一阶段：设备鉴定与描述符解码（2026-10-09）

### 要解决的问题

要给一块 **ThinkPad 拆机改装的外接键盘**（用户主力键盘，小红点重度使用者）救活触摸板：接 MacBook 后打字正常、**小红点原生可用**，但**触摸板完全无响应**。macOS 没有外接触摸板的通用驱动。

### 设备鉴定

| 项 | 值 |
|---|---|
| 设备名 | ThinkPad X1 Tablet Thin Keyboard Gen 3 |
| 代工 | Chicony |
| USB ID | VID `0x17ef`（联想）PID `0x60b5` |

设备枚举出 **3 个 USB HID 接口**：

1. **键盘接口**（UsagePage 1 / Usage 6）——普通打字键 + Fn 多媒体键，macOS 原生可用
2. **鼠标接口**（UsagePage 1 / Usage 2）——750 字节复合描述符，macOS 只认其中小红点部分
3. **厂商接口**（UsagePage 1 / Usage 0x80）——1 字节杂项报文（LED/热键），与触摸板无关

**鼠标接口描述符解码结论**（本项目第一个关键发现）：

- Report ID `0x02`：小红点，2 键 + 8 位相对 XY（macOS 已原生驱动）
- Report ID `0x10`：第二套相对鼠标——触摸板的"相对模式"
- Report ID `0x03`：**标准 HID 多点触控 digitizer**：5 指独立报文、16 位绝对坐标 X∈[0,1163]、Y∈[0,718]、接触计数、物理按压位——**触摸板本体**
- Report ID `0x04` 等 + 一组厂商 Output 报文：配置与模式切换通道
- 结论：**触摸板协议是公开的 HID 标准，不需要逆向私有协议**

### 诊断命令存档

```bash
# 枚举 HID 接口（system_profiler SPUSBDataType 对该设备无输出, 用 hidutil）
hidutil list | grep -i -E "0x17ef|thinkpad"

# 提取报告描述符（ioreg 必须用 IOHIDDevice 基类; 属性名是 "ProductID" 不是 "idProduct"）
ioreg -r -c IOHIDDevice -l -w 0 > /tmp/hid2.txt
# 取含 '"ProductID" = 24757' (0x60b5) 的块中的 "ReportDescriptor" 十六进制, 逐字节按 HID 规范解码
```

### 权限两连坑（解法沿用至今）

- `IOHIDDeviceOpen` 对鼠标类接口返回 `0xe00002e2`——必须授予 **输入监控**
- `CGEventPost` 缺 **辅助功能** 时**静默失败**（光标纹丝不动，极易误判成代码 bug）

## 第二阶段：Input Mode 切换突破（2026-10-10）

触摸板无响应的根因确认：出厂固件默认跑相对鼠标模式，多指 digitizer 模式要主机**主动下发标准 HID「Input Mode」Feature**（reportID 4，值 3）切换。两个细节坑：

- Feature buffer **首字节必须是 reportID**（`{0x04, 0x03}`），只传 payload 返回 kIOReturnSuccess 但模式不变
- 模式由设备记住，驱动重启无需重切

### digitizer Report 0x03 布局（1480 帧程序化全量解码钉死）

```
回调缓冲 len=30: r[0]=0x03(reportID 前缀) + 29 数据字节
finger k 数据起于 r[1+5k] (k=0..4), 每指 5 字节:
  [0] bit0=Confidence(1=真手指,0=手掌) bit1=TipSwitch bit2..4=ContactID
  [1..2] X 小端 (0..1163)   [3..4] Y 小端 (0..718)
尾部: r[26..27]=scan time  r[28]=接触计数  r[29] bit0=物理按压
```

**重大教训（烧掉两个会话）**：此前两轮会话的"无前缀"布局结论是错的——真根因是调试打印把 r[0] 打在行首、正文从 r[1] 起转储，肉眼解码整体偏移 1 字节。**规矩：二进制布局只信脚本对全量帧的自洽校验（tip 数==计数、坐标在量程、动作段分布吻合），肉眼读日志一律不算数。**

另一教训：多设备复合 HID 接口，绝不能靠一次混合手势抓包断定谁发哪个 rid——必须一次只动一个设备、清空日志、单独采集做对照（曾把 0x02/0x10 认反）。

## 第三阶段：手感对齐原生触控板（2026-10-12）

### 滚动"卡卡的"根因

纯像素滚动事件被 App 当**鼠标滚轮格子**，各 App 自己再做一层加速/平滑——快慢都顿挫，调增益治标不治本。原生丝滑靠**手势相位事件流**（type 22 连续滚动 + MayBegin/Began/Changed/Ended 相位 + 每事件配 type 29 手势 + 动量相位流），整包移植自 **Mac Mouse Fix** 的 `GestureScrollSimulator`。非显然语义：

- Ended 后部分 App（Xcode）按最后非零 Changed **自带续滚**——不接自家惯性时必须补零增量 momentumEnd 阻断
- 只碰未滚收 Cancelled 不收 Ended；动量期不发 type 29；行增量=像素/10

### 三指系统手势（私有 IOHIDEvent）

切空间/调度中心 = 构造 type 23 DockSwipe IOHIDEvent（motion 1横/2竖、flavor=DockPrimary、progress、velocity 子事件）塞进 type 30 CGEvent。`_SLEventSetIOHIDEvent` 未导出，用 MMF 生产做法内存 poke（`+0x18` 解引用 `+0xd0` 存指针）。`IOHIDEventCreate` 为 **5 参**签名（ctypes 读回验证）。缩放公式与"末帧同号→Ended/反号→Cancelled"规则均取自 MMF；结束事件需 200/500ms 重发规避系统手势卡死 bug。

### 多屏

光标钳制必须用**全部活动屏联合矩形** + `CGDisplayRegisterReconfigurationCallback` 热插拔刷新——只钳主屏会把光标困死在主屏（用户外接了右侧扩展屏）。

### 事件构造侧的零散铁律

- 按住期间移动必须发 `kCGEventLeftMouseDragged`，插 Moved 会被 App 取消该次点击（"点按偶尔不灵"根因）
- launchd agent 里 `CGEventPost` 到 `kCGHIDEventTap` 会被静默丢弃，用 `kCGSessionEventTap`
- TCC 授权绑定签名身份 → 自签长期证书 `tpkbd-sign`，重编译授权不失效
- 只重编译必须 `launchctl kickstart -k`，launchd 不自动换新二进制

## 第四阶段：补全功能（2026-10-12）

- **多显示⽰器**：双指右键（轻点+物理按压）与单指轻点左键（含双击/三击连击计数）
- **打字锁定**：libinput DWT 语义——敲键后 500ms 吞新触摸、在板手势放行（key 回调快照 touch_now）、物理键只挡新按下不挡松开（防卡键）
- **键位重排**：`hidutil UserKeyMapping` 按 VID/PID 匹配，ThinkPad 键盘 Win(LeftGUI)↔Alt(LeftAlt) 互换对齐 Mac 底排，MacBook 内置键盘不受影响；映射易失（重启清空）→ device_attached 里重刷

## 双指滚动精度与惯性交接修正（2026-10-19）

针对「手指滑动时细碎顿挫、松手惯性不自然」的反馈，先修复可由源码和回放验证的问题：

- 双指质心用浮点保存，保留半个传感器 count。旧实现先整除再乘增益，缓慢单指位移会让双指滚动交替出现零增量和两倍增量。
- FixedPt 滚动字段从当帧像素增量换算，保留小数行；整数行字段仍独立累积。旧实现把已取整的行数写入 FixedPt，浪费了 16.16 精度。接口语义参考 [Apple CGEventSetDoubleValueField](https://developer.apple.com/documentation/coregraphics/cgevent/setdoublevaluefield(_:value:))。
- 双指惯性速度改为单调时钟、28ms 时间常数的指数平滑，避免固定帧权重随报文频率改变；反向清除旧方向速度，松手前无报文的停顿也衰减速度（保留 20ms 传输余量）。
- 两指先后离板（2→1→0）留 60ms 交接窗口，等全部离板才启动惯性；剩余一指停留超过窗口则回到指针移动。旧逻辑会启动后立即被残留手指截停。代价是从双指主动切为单指移动最多等待 60ms。
- 惯性不足一像素的首帧被累积时，不再提前标记 Begin 已发送，保证下一个实际事件仍是 Begin。

验证：`./tests/run.sh` 使用真实 CoreGraphics 事件对象，但拦截所有 CGEventPost，只在内存中检查，不操作桌面。覆盖慢滚每帧精度、正反方向累计距离、FixedPt 字段、不同报文间隔、停顿/反向、惯性相位与总距离、先后抬指及残留单指超时；启用 AddressSanitizer 和 UndefinedBehaviorSanitizer。生产源码通过 `-Wall -Wextra` 编译。

这些测试验证计算与事件序列，不代表已证明与原生触控板手感一致。硬件报文节奏、应用处理和显示刷新仍需实机对比；本次保留原来的滚动增益、阻力曲线及 10ms 惯性定时器，没有加入额外移动平滑延迟。

### 中快速滑动：实测输入节奏与显示刷新重采样

用户反馈慢滑改善，中快速滚动在 ChatGPT/Codex 应用仍有卡顿。独立 `--capture` 监听器处于 disabled 状态，未收到事件，未把空采样当成性能结论。新增 SIGUSR1 触发的 30 秒驱动内采样：只记录触摸报文和发出的滚动事件，内存最多 16,384 行，结束后一次输出到现有日志，不记录键盘输入。

首轮有效采样 1,256 行：318 个相邻双指报文间隔的中位数 7.008ms，p95 9.049ms，范围 2.853–12.021ms；设备 Scan Time 每帧增量为 71/72（100us 单位，约 140Hz）。实际两块屏幕为 60Hz 和 75Hz。输入到达抖动与刷新不同步是候选原因，不据此声称已排除应用绘制方面的问题。

改动：

- 以设备 Scan Time 建立输入时间线（支持回绕、时钟异常回退），保留浮点累计位移。
- 双指触摸位移默认缓冲 12ms，在已有样本之间线性插值，按光标所在屏幕的 CoreVideo 显示时钟输出；没有预测未来运动。
- 惯性也改由显示时钟驱动。显示时钟不可用或超过 50ms 无回调时以 120Hz 定时器回退；空闲停止显示时钟与回退定时器。显示回调线程只唤醒主循环，手势状态仍只在主线程访问。
- 手势结束时先送完缓冲余量再 Ended，不丢距离、不向下次手势泄漏位移。可用 `TPKB_SCROLL_SMOOTH_MS=0` 对照原来的触摸直通路径（惯性仍按刷新驱动）。
- 代价：新增约 12ms 缓冲以及等待下一刷新帧的延迟；结束时的缓冲余量会在最后一次输出送完。该方案需要用户对平滑与跟手感进行实测取舍。

验证：原有测试及新增 60/75/120Hz、带 USB 到达抖动的匀速轨迹、方向变化、重复时间戳、队列溢出、扫描时钟回绕、结束距离守恒、结束后无输出均通过。ASan/UBSan 检查开启，UBSan 设为遇错立即失败。

部署后验证：后台服务、辅助功能授权及 HID 回调正常；光标所在内置屏的 CoreVideo 时钟启动成功，报告 60Hz。用户在相同应用中复测中快速双指滚动，反馈「更顺了，跟手也正常」，保留此版。外接 75Hz 的时序路径通过合成测试，尚未收到该屏幕的单独主观对比反馈。

最终短时实测采样 2,272 行：双指设备报文间隔中位数仍为 7.004ms，手势滚动输出间隔中位数变为 16.628ms、p95 17.402ms，符合内置屏 60Hz 节奏（收尾补余量会产生少量更短间隔）。采样已按 30 秒上限自动结束。

### 轻触左键偶发光标向下漂移（2026-10-19）

用户报告单指轻点偶发向下微移。本轮短时采样用户未复现主观异常，不据此声称捕获了现场故障。源码回放独立复现了明确漏洞：轻点要求每轴位移 `<=14`，指针死区却使用 Manhattan 距离 `<14`，因此 `(7,7)`、`(0,14)` 等偏移既能放行指针移动，也能在抬指时触发左键。新增测试在修复前于光标坐标断言失败。

修复：轻点、落指死区和落板跳变判断共用每轴闭区间；一旦实际移动过光标，本轮接触不能再触发轻点。落板跳变滤除仅在尚未进入指针移动、未发生物理按压且死区启用时运行，不会清掉已确认移动的判定。保留原有落板沉降抑制和已验证的双指滚动重采样。

验证：内存事件回放覆盖正负/斜向/阈值边界、超过落板初期窗口的微移、18-count 落板沉降、双击/三击不漂移、移动后不点击、死区关闭及物理按压拖移；同时运行完整滚动回归，ASan/UBSan 和生产 `-Wall -Wextra` 编译通过。间歇性硬件症状是否全部消除仍需日常使用反馈。

## 单指移动精度与速度曲线（2026-10-20）

原指针路径按每帧 `int(delta * 1.8)` 输出，零碎像素直接丢失；同样的传感器总位移拆成小帧与大帧，会得到不同的屏幕距离。光标路径也没有按手速变化的增益。

- 新增 `pointer_motion.h`：以每轴小数余量累积并四舍五入到最近像素，累计舍入误差控制在半像素内。没有位移的轴不释放余量，避免静止或竖移时横向漂移。
- 默认速度曲线以传感器速度 150～1500 counts/s 为过渡区间，使用 smoothstep 连续映射到基础倍率的 0.5～2 倍。基础倍率仍为 1.8，因此慢速约 0.9、快速约 3.6。这是为本板设计的曲线，需要日常使用反馈调节手感。
- 速度估计基于相邻原始坐标和 HID Scan Time（100us、支持回绕），无有效扫描时钟时回退单调接收时间。不能将落指死区累计位移当成一帧速度。速度提高用 12ms 时间常数平滑，减速用 6ms，使接近目标时及时降低增益；不对光标位置添加插值缓冲或预测运动。
- 落指、换槽/ContactID、落板跳变重锚和按压拖移抑制时重置运动状态；屏幕边缘钳制后丢弃被挡轴的小数余量。滑动/抬指后恢复指针时重新锚定。
- 新增 `TPKB_MOVE_ACCEL=0` 对照固定倍率模式（仍保留小数位移），`TPKB_MOVE_GAIN` 作为两种模式的基础倍率。

验证：固定 1.8 倍时十个 1-count 输入精确输出 18 像素；正反向累计距离对称；同样 100 counts 行程慢速输出 90 像素、快速输出 360 像素。另覆盖增益连续/单调/有界、不同上报频率同速、时钟回绕/USB 抖动、快速减速、静止轴不漂移、换指/滚动恢复/边缘的状态重置。完整轻点防漂移、连击、拖动及滚动回归在 ASan/UBSan 下通过。硬件的触摸坐标分辨率及现有落指死区仍是精度边界。

## 双指捏合缩放（2026-10-20）

新增与滚动分流的原生缩放事件：采用 [Mac Mouse Fix TouchSimulator](https://github.com/noah-nuebling/mac-mouse-fix/blob/master/Helper/Core/Touch/TouchSimulator.m) 的 type-29/subtype-8 布局，field 113 为增量 magnification、field 132 为 IOHID 手势相位。AppKit 内存转换验证为 NSEventTypeMagnify，并正确映射 Began/Changed/Ended/Cancelled。没有用快捷键模拟缩放。

识别：跟踪两个 ContactID 的质心与间距。两指平移进入滚动；间距变化超过 max(8 counts, 初始间距的3%)、相对质心平移占优且有连续径向运动时进入捏合。一根手指固定、另一根张开/合拢也可识别；孤立的落板跳变不作为连续捏合。为防止两种事件混发，同一对接触一旦确认滚动或缩放便锁定，抬指后可切换。

缩放：按两指距离比生成相对缩放量，在对数域沿用12ms缓存与显示刷新重采样；张开放大、合拢缩小，与自然滚动方向和指针加速独立。结束时送完余量，抬指发 Ended，按压/换指/第三指/设备移除发 Cancelled。缩放结束后仍在板上的一指暂不驱动指针，避免尾指漂移。物理按压优先，保留食指按住左键、中指拖动的操作。

配置：`TPKB_PINCH=1` 默认开启，0恢复双指仅滚动；`TPKB_PINCH_GAIN=1.0` 调整灵敏度（0.1～4）。目标应用需要支持原生 magnify 事件。

验证：原滚动/指针/轻点测试全部保留；新增正反向缩放比例、反转、单指固定捏合、平移滚动互斥、带重采样滚动距离、相对抖动/孤立跳变、换ContactID/按压/第三指/设备移除取消、尾指不漂移、用户双指按压拖移姿势。另用 AppKit 对生产事件工厂做原生类型/相位/正负缩放量测试。所有测试在 ASan/UBSan 下通过；实机应用兼容性与手感另行验证。

部署后驱动启动、辅助功能授权及 HID 回调正常。30秒实机短时采样记录到15组完整的缩放手势（15 Began、290 Changed、15 Ended），包含正负缩放增量；采样已自动结束。该结果证明硬件手势已走到缩放输出，应用表现与主观灵敏度仍以用户试用为准。

Safari 试用反馈：放大、缩小可用，但合拢不能像内置触控板一样进入标签页概览。已有原生与 DIY 缩放量范围重叠，未据此提高倍率。将捏合注入点从 session 改为 TouchSimulator 使用的 HID 通道后，用户确认仍然只能缩小页面，该调整没有解决概览问题。
